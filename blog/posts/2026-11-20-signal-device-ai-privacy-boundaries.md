## What Signal announced

Signal's November 20, 2026 announcement highlights a challenge for device-level AI assistants: sensitive information can become accessible outside the application that originally protected it.

Signal describes screenshot restrictions for iOS 27 and supported Android configurations. It acknowledges that these protections are incomplete and calls for stronger operating-system controls and documentation covering other access routes.

I agree with the underlying concern. An assistant's access should have a clear relationship to the task the user authorized.

## Should permission to assist imply broad access to the device?

I do not think broad access should be the default assumption.

If I ask an assistant to organize my calendar, I expect it to use information relevant to scheduling. An unrelated private conversation should remain outside that task.

I would prefer permissions that specify the information required, the purpose of access, and when that access ends. Additional access should require a separate, understandable decision.

## Are screenshot restrictions an adequate solution?

I see them as a useful measure within a broader architecture.

I would also examine notifications, local files, accessibility interfaces, and connected services. Restricting one route has limited value if equivalent information remains available elsewhere.

My preference would be coordinated controls across the operating system, application, and assistant, so developers can establish boundaries that users can understand and rely on.

## How should we consider other people in a conversation?

I believe this deserves more attention in consent design.

A conversation includes information from several people. One participant enabling an assistant can therefore affect others who never chose to use it.

I would favor minimal collection and explicit selection of the content needed for a task. Where an assistant could collect an entire conversation, the interface should make that scope and its consequences clear before processing begins.

## What should happen when access is revoked?

I would distinguish stopping future access from managing information already retained.

Users should be able to understand what was collected, where it was stored, and which deletion options are available. Revocation should have a clear effect, rather than leaving users to guess whether an assistant can still use previously captured information.

I would also want retention limits established before collection, so deletion is part of the design.

My view is that useful AI assistance depends on trust that can be explained and enforced. I want a clear account of what an agent can observe, why it needs that information, and what happens to it afterward.
